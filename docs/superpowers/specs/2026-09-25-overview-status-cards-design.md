# 概览页扫描与备份状态卡设计

## 目标

在概览页把项目扫描、Codex 数据扫描、本地备份和迁移/恢复的状态集中展示，并复用数据页已有的四项数据统计，让用户在开始操作前和切换页面后都能判断当前准备状态与最近一次操作结果。

## 范围

- 将项目扫描状态卡放到“云端备份已关闭”卡片上方。
- 在现有概览四项总览指标下方增加数据页的四项指标：对话、技能、插件、生成图片。
- 增加四个统一状态卡：项目扫描、Codex 数据扫描、本地备份、迁移/恢复。
- 将备份和迁移/恢复的运行结果提升到 AppContent 管理，使页面切换不会丢失本次会话状态。
- 增加中文和英文文案、无障碍名称、状态样式及组件测试。
- 版本升级为 0.1.9，并同步更新双语 README、CHANGELOG、状态/验收文档和发布材料。

## 状态模型

### 扫描状态

- 项目扫描继续使用现有 `LocalScanState`：`idle`、`running`、`complete`、`partial`、`failed`。
- Codex 数据扫描由现有 `loading`、`inventory` 和 `codexScanFailed` 推导：加载中、已完成、失败或尚未开始。
- 启动扫描完成后立即在概览页反映结果；不新增持久化字段。

### 操作状态

- 本地备份和迁移/恢复在 `AppContent` 保存会话级结果：未执行、进行中、完成、部分完成、失败。
- `BackupsPage` 在本地备份或本地恢复结束时报告结果；`ReceivePage` 在 ReHome 导入完成或回滚/失败时报告结果。
- 页面切换不会清除状态；应用重启时不恢复旧的“已完成”状态，避免把历史操作误认为当前会话已验证。
- 现有详细结果、错误原因和解决方案仍保留在备份/迁移页面；概览卡只展示摘要并提供进入对应页面的按钮。

## 页面布局

概览页顺序固定为：

1. 页面标题和快捷操作。
2. 第一组四项总览指标：扫描项目数、对话总数、扫描文件数、计划任务状态。
3. 第二组四项数据指标：对话总数、技能、插件、生成图片。
4. 四个状态卡：项目扫描、Codex 数据扫描、本地备份、迁移/恢复。
5. 云端备份已关闭提示卡。
6. 完整本地备份说明和操作说明。

状态卡在窄屏下单列，在宽屏下使用两列；成功、进行中、部分完成和失败使用现有主题色、警告色和错误色，不新增颜色体系。

## 交互与错误处理

- 点击状态卡中的操作按钮进入项目、数据或备份与迁移页面。
- 操作进行中沿用现有全局任务提示；概览卡显示“进行中”，不允许误认为已完成。
- 失败状态只显示通用摘要，详细原因和解决方案仍由全局错误区或对应页面提供。
- 迁移/恢复包含文件恢复、ReHome 导入和回滚失败等现有结果语义；不得把仅导出迁移包误报为已恢复。

## 非目标

- 不改变备份包含/排除规则、Codex 凭据保护规则、云端逻辑或恢复事务逻辑。
- 不把操作状态写入用户配置或新增数据库迁移。
- 不声称原生 Codex 会话已经续接成功；概览页只反映应用已经完成的本地操作和现有验证结果。

## 验收标准

1. 概览页的项目扫描状态出现在云端关闭卡片上方。
2. 概览页第一组指标下方显示对话、技能、插件、生成图片四项数据统计，数据与数据页一致。
3. 四个状态卡能分别显示扫描、备份和迁移/恢复的运行结果；项目切换页面后状态仍在。
4. 失败、部分完成和进行中状态不会显示为成功完成。
5. 中文和英文界面均有完整文案，按钮和状态卡具有可访问名称。
6. 现有测试、构建、完整验证和安装包检查通过；0.1.9 安装包可安装并保留用户数据。
7. GitHub `main` 通过普通 SSH 443 快进推送，`v0.1.9` Release 仅包含安装包及 SHA-256 文件。

## 验证策略

- React/Vitest：覆盖概览两组指标、四个状态卡、状态变化和页面切换保持。
- TypeScript/Vite：类型检查和生产构建。
- 项目既有 Rust/许可证/打包验证：完整执行 `scripts/verify.ps1` 与 `scripts/package.ps1 -SkipBootstrap`。
- 安装验证：卸载已安装 0.1.8，安装 0.1.9，读取注册表和安装文件版本，并确认用户配置仍存在。
- 发布验证：重新检查远端 `main`、标签、Release 状态、资产数量和 SHA-256；不上传其他文件。
