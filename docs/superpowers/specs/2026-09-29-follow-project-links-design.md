# 项目链接目标纳入备份设计

## 目标

项目备份应包含选定项目根目录内通过 Windows 目录联接、符号链接或其他文件系统重解析点可到达的实际文件内容。链接目标不再被错误显示为普通“文件缺失”，恢复后目标内容以普通文件和目录形式存在，确保在新设备上可直接使用。

## 已确认的根因

当前扫描和备份流程在以下位置主动关闭了链接跟随：

- `desktop/src-tauri/src/core/local_discovery.rs` 的项目文件计数使用 `follow_links(false)`，遇到重解析点会跳过。
- `desktop/src-tauri/src/core/restic.rs` 的指纹计算和 `stage_tree` 使用 `follow_links(false)`，遇到重解析点会写入缺失或提示记录。
- 截图中的目标位于 `Product-video（推广视频生成）` 项目根目录内部，属于项目可到达内容，不应再按缺失处理。

## 范围和边界

### 纳入范围

- 项目根目录内的目录联接、符号链接和 Windows 文件系统重解析点。
- 链接指向的普通文件和目录内容。
- 项目文件计数、备份指纹、备份清单和恢复结果。

### 安全边界

- 链接目标必须解析到当前选定项目根目录内部，才会自动跟随。
- 指向项目根目录外的链接不自动跨目录读取；程序显示目标路径并要求用户把目标目录单独加入项目选择。
- 不跟随链接进入备份仓库、Codex 数据目录或其他受保护范围。
- 保留现有 Codex 数据安全排除规则；本设计不改变登录凭据、Cookie 等排除逻辑。
- 不恢复为新的目录联接，避免恢复到另一台设备后产生失效链接或越界访问。

## 处理流程

1. 读取链接项的实际目标并规范化路径。
2. 校验目标存在、可读、位于当前项目根目录内，且不与已访问的实际目录身份重复。
3. 对目录目标递归计数、计算指纹并复制到链接所在的相对位置；对文件目标复制实际文件内容。
4. 记录实际纳入的文件数量和字节数；成功纳入的链接不计入 `missing`。
5. 目标不存在、无权限、越界或检测到循环时，记录明确的链接问题，包括链接路径、目标路径和处理建议。
6. 恢复时按备份中已经实体化的目录和文件写回，不创建符号链接或目录联接。

## 用户界面

- 将成功纳入备份的链接从“文件缺失”列表移除。
- 对未能纳入的链接显示“链接目标未纳入备份”，并明确是目标不存在、权限不足、越出项目范围还是循环链接。
- 项目文件数量和备份结果中的文件数量包含成功实体化的链接目标内容。
- 操作说明增加：项目内链接会随项目内容备份；项目外链接需要单独选择目标目录。

## 测试验收

- Windows 合成目录联接：项目内目标被计数、指纹变化可检测、备份清单不含缺失项。
- Windows 合成文件链接：目标内容出现在链接相对路径，恢复后内容可读取。
- 项目外目标：不被自动读取，产生带目标路径的明确问题。
- 循环链接：扫描终止，不出现无限递归，问题可定位。
- 目标被删除或无权限：保留普通文件备份结果，并准确报告该链接问题。
- 既有普通文件、Git 元数据、Codex 安全排除、恢复事务和页面切换行为保持不变。
- 通过 Rust 测试、前端测试、类型检查、构建、许可证检查、安装包哈希和发布清单检查。

## 非目标

- 不自动备份项目根目录外的整个目录树。
- 不恢复原始链接对象。
- 不取消 Codex 凭据和运行时数据的安全排除。
- 不改变云端备份逻辑。
