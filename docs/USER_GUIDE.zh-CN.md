# ENHE Codex Backup 中文使用说明

## 第一次使用

应用启动后先看“概览”。云端状态显示为“已关闭”是正常默认状态；这不会阻止本地项目发现、备份、历史浏览和恢复。

启动时应用会先读取已保存的配置，再扫描配置中的 Codex 数据位置。Codex 路径未配置时会尝试当前 Windows 用户的 `.codex`；找不到时会显示实际尝试路径，可直接点击“选择 Codex 数据位置”重新选择。项目发现支持配置扫描根目录和自动扫描开关：开启后在配置范围内后台发现候选；未设置扫描根目录时使用本机固定磁盘。更改扫描范围后重新扫描，以最新结果确认候选及权限提示；发现候选不等于已备份，请检查项目勾选并保存。关闭自动扫描后仍可手动添加项目目录。

如果遇到受保护的 Windows 目录，应用会安全跳过并只显示无权限目录数量，不会把几十条“拒绝访问”堆在页面中。需要时在“项目”勾选“扫描受限目录时申请管理员权限”，再点击“以管理员权限重新扫描”并按 UAC 提示操作。

1. 打开“项目”，勾选要纳入完整备份的项目；非 Git 普通目录可在“手动添加项目目录”中输入并加入，然后保存。
2. 打开“数据”，确认 Codex 数据位置并保存。点击字段旁的文件夹按钮即可打开 Windows 路径选择窗口；路径也可以手动输入，支持本机磁盘、移动盘或含中文/空格的目录。
3. 打开“备份与迁移”，选择用于存放加密仓库的备份目录，输入恢复密码，点击“开始本地备份”。密码用于加密 restic 仓库，忘记密码无法恢复仓库。
4. 需要计划任务时勾选当前用户计划任务，并勾选“记住密码”。密码只用当前 Windows 用户的 DPAPI 保护；未记住密码时，计划任务无法读取密码并会报告错误。
5. 不熟悉流程时打开“操作说明”，按流程图从自动扫描一路完成到恢复或离线迁移。

备份开始后可以在应用内切换页面，备份和结果会继续保留；请保持 ENHE Codex Backup 打开，不要退出应用或关机。备份期间关闭云端不会影响本地过程。应用只管理自己启动的 restic 子进程，不会扫杀其他程序。

“备份仓库”就是保存加密快照的存储目录，不是源项目目录，也不是恢复目标目录。请单独保管整个仓库和恢复密码；“记住密码”只对当前 Windows 用户有效，不能替代迁移到另一台电脑时所需的密码。

## 查看和恢复

在“备份与迁移”确认仓库位置并输入恢复密码，点击“刷新本地备份”查看快照。选择与仓库、原始资料分开的新空目录作为“恢复目标目录”，然后在对应快照上点击“恢复”。应用先恢复到私有暂存目录，检查 `enhe-payload` 和 manifest，再提交到 `<恢复目标目录>/backup-<logical_backup_id>/`；界面返回的实际恢复路径为准。

该目录内的布局来自备份清单：`manifest.json` 保存来源、计数、排除项和缺失项；`codex/` 保存 Codex 文件；`projects/<项目 ID>/` 保存项目文件，目录名不是原项目名；需要时还有 `git-metadata/<项目 ID>/worktree/` 和 `common/`。应用会修复已识别 worktree 的 Git 指向，因此检查或移动恢复结果时应保留整个布局，不要只单独移动 worktree 文件夹。

如果 `backup-<logical_backup_id>` 已经存在，操作报告冲突并停止，不覆盖它；请选择新的空目标目录。恢复后的文件不会自动执行脚本、Git hooks 或 MCP 配置；请先检查内容，再自行打开项目。

文件恢复成功不代表 Codex 中的原对话已可见或能继续。恢复到隔离目录后，应先检查清单、项目文件和会话数据；将其应用到真实 Codex 配置目录是单独的操作，需要备份现有配置并另行验证兼容性、路径、索引和对话续接。不要自动覆盖正在使用的 `.codex`，也不要把文件完整性或项目登记成功当作对话续接已验证。

## 完整备份范围

从 0.1.3 起，完整本地项目备份保留所有可读取的普通文件，包括隐藏文件、`.git`、未提交/未跟踪/被 `.gitignore` 忽略的文件、`node_modules`、构建产物、缓存，以及 `.env`、私钥、Token 等敏感文件；不按扩展名筛选。相关 worktree 元数据仍保留。文件更多会增加首次备份的时间和临时磁盘占用，请把备份仓库放在项目目录之外。

项目中的敏感文件进入 restic 加密仓库：请使用独立的强恢复密码，并和仓库分开保管，切勿公开恢复结果或上传到 GitHub。云端默认关闭，不会自动上传。**Codex 数据位置仍独立应用原有安全排除规则**，包括已知登录凭据、Cookies、私钥、`.env`、依赖、指定缓存及运行时锁文件。Codex JSONL/SQLite 的活动会话采集规则不变。符号链接及文件系统重定向不跟随；不可读取或不支持的内容会进入缺失清单，并使备份标记为部分完成，而不是假报全量成功。

在“项目扫描目录”输入 `F:\Projects` 时，应用按其直属文件夹列出项目，名称与文件夹一致；项目内部 `.next`、测试样例等只计入文件，不再单列。留空则使用可取消的全盘智能发现，仍有深度/时间边界。重新扫描替换当前发现结果，已保存的手动与历史路径单独列出。

文件数量在后台递归统计，包含隐藏、Git、依赖、构建及敏感文件；统计期间显示“正在统计文件…”，完成后显示实际数量。无权限、重定向或取消导致不完整时显示部分统计及跳过项；真正的空目录才显示 0 文件。计数仅代表扫描时可枚举的普通文件数量，不保证随后能读取其内容；实际备份结果、额外 Git 元数据及活动文件变化以 `manifest.json` 为准。

## 将完整备份带到另一台电脑

等待备份完成后复制整个加密仓库目录，在新电脑将本地仓库位置指向该副本，输入原恢复密码，刷新快照，再恢复到新的空目录。不要只复制某一个快照文件或仓库子目录；恢复依赖完整仓库和密码，原电脑保存的 DPAPI 密码不能代替它们。此流程恢复的是文件，仍需按上节单独验证真实 Codex 配置的应用与对话续接。

## ReHome 迁移

“导出 ReHome 迁移包”和“导入 ReHome 迁移包”只处理勾选的项目、对话、Skills、插件和生成图片，并应用 ReHome 自身的安全排除规则（包括不带走 `.git` 等内容）。全选也不会变成 restic 完整备份；单独勾选对话不包含项目文件。导出的 `.rehome` 文件不是加密 restic 仓库，不能当作完整备份或其密码保护的替代品。

导入时选择 `.rehome` 文件，核对包内内容及页面显示的 Codex 数据位置；包内有项目时再选择项目保存位置。预览会列出将写入的准确路径，项目位于 `<项目保存位置>/<包内项目名>/`，会话和索引写入计划中的目标 Codex 位置，与上述本地快照恢复的目录布局不同。保存工作并完全退出目标 Codex 后，再确认执行；发生冲突时先查看计划，再选择保留本机文件或使用包内容，替换前的安全备份由应用管理。

导入失败时先查看错误及迁移记录，按可用的恢复或回滚操作处理，不要手工覆盖真实 `.codex`。文件和索引校验通过后，仍需重新打开 Codex，单独检查原对话是否可见并能继续发送消息；在此之前，对话续接状态仍是未验证。

## 云端（可选）

云端默认关闭。要配置 OneDrive：

1. 在“设置”填写 rclone 配置文件、远端名称、OneDrive 路径和云端仓库路径。
2. 点击“开始 OneDrive 配置”，按向导出现的问题逐项回答。取消时不会启用云端，也不会上传快照。
3. 配置文件生成后仍需手动勾选“启用云端备份”并保存设置。
4. 只有点击“测试 OneDrive 连接”或某个快照的“上传此快照”时，应用才会启动远端操作。

本地备份不依赖云端。授权失效、断网、限流或超时只影响显式的云端操作；本地快照和历史保留在本机。

## 语言和外观

左侧语言按钮切换简体中文/English；设置中的外观可选浅色、深色或跟随系统。语言切换不会清除表单；键盘用户可以通过 Tab 到达导航、表单、错误和操作按钮。

## 常见错误

- “恢复密码必填”：没有传入密码，也没有可用的当前用户 DPAPI 密码。
- “仓库目录重叠”：本地仓库或恢复目录位于源资料内部，请更换到独立目录。
- “目标已存在”：选择新的恢复目标；应用不会覆盖原目标。
- “云端配置不完整”：先完成 OneDrive 配置并保存，再打开云端开关。
- “计划任务不可用”：当前用户任务计划未能注册或读取；本地手动备份仍可继续。
- “本机项目扫描已部分完成”：部分目录无权限、被跳过或扫描被取消；页面会给出聚合统计，已经发现的候选仍可手动勾选，不能把部分结果当作全盘完成。

离线标准 restic 恢复命令见 [离线恢复说明](OFFLINE_RESTORE.zh-CN.md)。当前实际验证边界见 [STATUS](STATUS.md)。
